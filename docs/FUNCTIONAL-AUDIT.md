Audit date: 2026-09-25. Production URL: https://helix-ai-two.vercel.app. No Supabase credentials were present in this environment, so live Auth and database calls were not executed. `scripts/verify-crm-contact-roundtrip.mjs` skips until `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and `CRM_TEST_CLIENT_ID` are set. ## Auth trace (why the confirmation email can be missing)

1. Signup calls `supabase.auth.signUp` in `lib/auth/sign-up.ts`. The screenshot ("Check your email") is that success branch: Supabase returned a user and no session, which is what happens when **Confirm email** is on. The screen was not a timer. It also did not show a Supabase error.
2. Before this change, `emailRedirectTo` was `` `${process.env.NEXT_PUBLIC_SITE_URL || 'http://localhost:3000'}/auth/callback?next=/dashboard` ``. If `NEXT_PUBLIC_SITE_URL` is unset or still `http://localhost:3000` on Vercel, the link in the message points at the developer's machine, and Supabase may reject the redirect if that URL is not allow-listed.
3. Code cannot make Supabase's built-in mail server deliver to an arbitrary inbox. That server is rate limited and, on many projects, only delivers to members of the Supabase organization. A custom SMTP provider is required for a real customer.
4. If the address was already registered, Supabase can return a user with `identities: []` and no error. The old screen still said a message was sent. That case is now an "account already exists" error.

## Schema notes

- `deals.stage` allows only `DEMO_BOOKED`, `QUALIFIED_TO_BUY`, `UNQUALIFIED_TO_BUY`, `DECISION_MAKER_BOUGHT_IN`, `CONTRACT_SENT`, `CLOSED_WON`, `CLOSED_LOST` (`supabase/migrations/202609070002_crm_intelligence.sql`). `proposal_sent` and `studio_completed` are not valid.
- `contact_facts` uses `field_name` / `field_value`, not `fact_key`.
- `clients.monthly_fee` is not in the migrations. Billing and reports no longer select it.
- New migration `supabase/migrations/20260925120000_functional_writes.sql` adds `contact_inquiries`, `site_documents`, and tenant insert/update policies for contacts and deal insert for client users. It does not drop or rewrite existing rows.
